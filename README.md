# TFT Set 18 ダメージシミュレーター

チャンピオン・アイテム・特性補正・敵の防御を入力すると、戦闘開始から30秒間のダメージをイベント順にシミュレーションし、累積ダメージ・DPS・グラフ・ログを表示するブラウザアプリです。サーバーやネット接続は不要です。

## 起動方法

1. このフォルダ(`tft_sim`)をそのままパソコンに置く(`img` フォルダも一緒に)。
2. `index.html` をダブルクリックして、Chrome / Edge / Safari などのブラウザで開く。

入力内容はブラウザに自動保存されます(同じブラウザで開き直すと復元)。

## 遊び方(使い方)

画面は上から **A → B → C → D** の順に操作します(広い画面では D の結果が右側に表示されます)。

| パネル | 内容 |
|---|---|
| A. チャンピオン | 画像カードを選ぶ → ★(1〜3)を選ぶ。ステータスとスキルが自動入力される。追加AD・AP・役割だけ常に表示。詳細は「ステータス詳細 / マナ詳細 / スキル詳細」を開いて編集 |
| B. アイテム | 3つの枠をタップすると一覧が開く。選ぶと数値と効果が自動入力される。通常版/レディアント版を切り替え可。「数値を編集」で手直し可 |
| C. 特性・追加補正 | 特性などの補正値(追加AD/AP/AS/クリ/増幅、ラピッドファイア等)。使うときだけ開く |
| D. シミュレーション | 敵の物理防御・魔法防御・耐久力、戦闘時間を入れて「計算実行」。結果・グラフ・イベントログ・計算の前提を表示 |

- 「初期値に戻す」で入力を初期化、「テスト実行」で検証テストを実行します。
- カスタムチャンピオンを選ぶと、すべて手入力で使えます。
- 数値を入力しない項目は 0 扱いです(推測値は入れていません)。

## ファイル構成

```
tft_sim/
├─ index.html   画面の構造(パネルの枠・読み込むファイル)
├─ style.css    色・レイアウト・レスポンシブ(ダークモード対応)
├─ script.js    計算ロジック(ステータス・防御・シミュレーション)+ 画面描画 + ボタン/入力のイベント処理
├─ database.js  データ定義(チャンピオン・アイテム・画像の対応・データ版 DATA_VER)
├─ save.js      セーブ・ロード(ブラウザの localStorage)
├─ tests.js     検証テスト(「テスト実行」ボタンで実行)
├─ README.md    このファイル
└─ img/
   ├─ champions/  チャンピオン画像
   └─ items/      アイテム画像
```

`index.html` の読み込み順(database → save → script → tests)は変えないでください。

## 計算の前提(主なもの)

- 通常攻撃ダメージ = 基礎AD × (1 + 増加AD/100)。クリティカル期待値(基礎クリ率25%・倍率1.4)とダメージ増加を掛ける。
- スキルの「(AD)/(AP)」表記 = 基礎値 × (1 + 増加AD/100)(APなら × (1 + AP/100))。スキルは通常クリティカルしない(インフィニティ・エッジ / ジュエルガントレット装備時のみ)。
- 増加ステータスは加算。例外: ブルーバフはAD/APを加算後に割合増加、アダプティブヘルムは毎秒マナ・攻撃ごとマナを割合増加。
- ASは 基礎AS × (1 + 増加ASの合計)。上限 5.0。
- マナ: 毎秒1回復 + アイテム分、スキル発動でマナ0。詠唱中・スキル中は通常攻撃をせず、マナ回復もしない。
- 敵の防御: 物理 = 100/(有効物理防御+100)、魔法 = 100/(有効魔法防御+100)、その後 × (100−耐久力)/100。通常攻撃は物理、スキルはスキルの種別。ラストウィスパーは物理防御、ヴォイドスタッフは魔法防御を30%貫通(常時)。
- ジャイアントスレイヤーはタンク特攻が常時発動する前提で、ダメージ増加を2倍(通常30% / レディアント60%)で入力済み。
- 燃焼・重症・回復は計算しません。

詳細は画面D内の「計算の前提」を開いてください。

## データの編集方法(開発メモ)

数値の変更・追加は基本的に **`database.js`** だけで行います。

- **チャンピオンを直す/足す**: `CHAMP_DATA` を編集。★1/★2/★3 は `[★1,★2,★3]` の配列。スキルは `skill:{...}`(種別は `type:'phys'|'magic'|'true'|'mix'`)。足したら `CHAMPS` にも名前を追加し、画像は `CHAMP_IMG` に登録。
- **アイテムを直す/足す**: `ITEM_DATA` の `D('名前',{通常版},{レディアント版})`。`ad, ap, asPct, critPct, amp, manaRegen, atkMana, armorPen, mrPen` などの数値と、効果ブロック `fx`(時間経過スタック `ts`、攻撃スタック `as`、追加ダメージ `ex`、燃焼 `bn`、条件付き増幅 `ca` など)を使う。足したら `ITEM_NAMES` に名前、`ITEM_IMG` に画像を登録。
- **データを更新したら `DATA_VER` を +1**: 保存済みのアイテム枠が最新のデータで読み直されます(チャンピオンや入力値は残る)。
- **画像を追加する**: `img/items/` または `img/champions/` にファイルを置き、`ITEM_IMG` / `CHAMP_IMG` にパスを書く。

## テスト

画面の「テスト実行」ボタンで `tests.js` のテストを実行します(仕様書10章の12項目 + 詠唱・アイテム・チャンピオン・防御などの追加分)。結果は D パネルの上部に「N/N 合格」と PASS/FAIL 一覧で出ます。

## 既知の前提・注意

- 巨人の誓いは攻撃時のスタックのみ(被ダメージスタックは未対応)。
- ストライカーフレイルのスタックは AS×クリ率×持続 で近似。
- 一部チャンピオンのスキル挙動(アフェリオスの追撃、アジールの置換攻撃、エズリアルの特殊スキルなど)は、記載のない部分を近似しています。内容は画面Aのチャンピオン注を参照してください。
